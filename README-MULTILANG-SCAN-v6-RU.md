# Code Security Analyzer — Scan Setup & Multi-language Paths v6

**Накладное обновление для Code Security Analyzer 9.0 RC1 с уже установленными UI v1–v5.**

## Что изменилось

1. На вкладке «Анализ кода» перед запуском аудита появился видимый список **«Модель для аудита»**, использующий уже имеющийся `MainController.scanModelComboBox`. Список заполняется из Ollama через существующий `loadAvailableModels()`; ручное переключение действительно применяется в `handleStartScanClick()` (а также в существующих путях генерации для Java и экспресс-анализа).
2. Добавлена кнопка **«Обновить модели»**. Последний выбранный тег модели сохраняется через `java.util.prefs.Preferences`; при следующем запуске восстанавливается, если тег есть в списке.
3. Адаптивная панель `FlowPane` имеет светлую и тёмную стилизацию. Рядом перечислены поддерживаемые **для аудита** семейства языков. При узком окне элементы панели переносятся.
4. Исправлена типичная причина `Cannot run program "semgrep"`, когда анализируется проект вне корня `code-security-analyzer`: бинарный Semgrep ищется в **доверенной папке самого анализатора** (`user.dir` или `-Danalyzer.home=...`), а не внутри выбранного проекта. Ручная настройка `-Danalyzer.semgrep.executable=...` сохраняется. Если бинарник не найден, используется PATH с явной ошибкой при неудачном запуске.
5. Добавлены 3 JUnit-теста для resolver `SemgrepExecutableResolutionTest.java` (работа проверяется тестом на Windows, без запуска реального Semgrep и без сетевых запросов).

## Важно об области поддержки

**Уже реализовано до v6:** основной `UnifiedScanService`, `FileAnalyzerImpl`, `CodeParserImpl`, Semgrep и LLM-пайплайн допускают Java, Kotlin, Scala, C, C++, Python, JavaScript, TypeScript, PHP, Ruby, Go, Rust, C#, SQL и соответствующие расширения, приведённые в UI. Качество обнаружения по разным языкам НЕ равно и требует отдельных экспериментов; `p/default` не покрывает все возможные CWE.

**Пока Java-only:** Fix Recommendation / Fix Validation с проверкой `javac`, оценка публичного Java API и испытания исправлений на учебных Java-кейсах. Нельзя интерпретировать Java-валидацию как доказательство корректности Python, Go, JS или C++. Если нужен полноценный multi-language **autofix**, это отдельный этап с подходящими синтаксическими проверками/компиляторами и тестами для каждого языка.

**Текущая неполнота LLM:** `PARTIAL_RESPONSE`, `NEEDS_REVIEW` и диагностические ошибки Semgrep не должны превращаться в «уязвимостей нет». `0` находок не доказывает безопасность.

## Установка

1. **Закройте JavaFX-приложение**, сохраните рабочие результаты экспериментов.
2. Распакуйте содержимое ZIP в корень `code-security-analyzer` рядом с `pom.xml`.
3. В PowerShell:

```powershell
cd "E:\001 Satbayev University\diplom\Новая папка\code-security-analyzer"
$env:JAVA_HOME = "C:\Program Files\Eclipse Adoptium\jdk-21.0.12.101-hotspot"
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
.\.venv-semgrep\Scripts\python.exe .\apply_multilang_scan_v6.py
.\mvnw.cmd clean test
```

Установщик **до записи** проверяет наличие v5 и ожидаемые Java/FXML-фрагменты. Создаёт резервные копии в `ui-theme-backup/<date>-scan-v6`. При повторном запуске сообщает, что всё установлено. Если найден конфликт с ручными правками, **не применяет** небезопасное текстовое изменение.

## Проверка Semgrep и Ollama

```powershell
ollama list
Test-Path ".\.venv-semgrep\Scripts\semgrep.exe"
.\.venv-semgrep\Scripts\semgrep.exe --version
```

При запуске из IntelliJ обычно `user.dir` указывает на `code-security-analyzer`. Если IntelliJ использует другую рабочую папку, задайте **VM options** (путь приведён только для примера):

```text
-Danalyzer.home=E:\001 Satbayev University\diplom\Новая папка\code-security-analyzer
```

Либо явно задайте проверенный исполняемый файл:

```text
-Danalyzer.semgrep.executable=E:\001 Satbayev University\diplom\Новая папка\code-security-analyzer\.venv-semgrep\Scripts\semgrep.exe
```

Не задавайте исполняемый файл, находящийся внутри недоверенного проверяемого репозитория. Если `p/default` не удаётся скачать, Semgrep честно сообщит о сетевой или конфигурационной ошибке.

## Короткая проверка UI

1. Запустите приложение. До выбора проекта увидите список локальных моделей Ollama.
2. Выберите модель, например `qwen2.5-coder:7b`. Нижняя строка покажет выбранный тег.
3. Выберите папку с `.py`, `.js`, `.go`, `.java` или `.cpp`; в дереве включите «Только исходники».
4. Отметьте нужные файлы и запустите анализ. При включённом фильтре проверяются только **видимые отмеченные** файлы.
5. Сверьте диагностику Semgrep, число успешных/частичных ответов LLM. Повторите с другой моделью и сохраните результаты отдельно.
6. Перезапустите приложение и убедитесь, что ранее выбранная модель восстановлена (если она остаётся доступной).
