# Code Security Analyzer — Web 1.3: журнал экспериментов

## Назначение

Патч устанавливается **поверх Web 1.2**, не изменяет JavaFX, Java-сервисы,
запуск Semgrep, Ollama, компиляцию и настройки Spring Boot. Новая секция
**05 / Эксперименты** расположена под блоком исправлений на главной странице.

Возможности:

- После каждого запроса «Сгенерировать и проверить исправление» создаётся
  запись: имя файла, модель, находка, результат генерации, Java/API,
  итог проверки Java, завершённость и количество находок Semgrep до/после.
- SHA-256 исходника и предложения рассчитываются **в браузере** (если Web Crypto
  доступен; localhost поддерживается). Содержимое исходника и предложения,
  diff и полные логи **не сохраняются** в истории.
- Дополнительно можно вручную отметить два функциональных сценария как
  PASSED, FAILED, SKIPPED или NOT_CHECKED, указать имя внешнего файла лога и заметку.
  Для PASSED имя лога обязательно. Эти статусы всегда помечены как
  `USER_DECLARED_EXTERNAL`: **сайт не запускал функциональные тесты**.
- Журнал хранится в `localStorage` браузера на данном компьютере/профиле
  (`csa-web13-experiments-v1`), до 100 последних записей.
- Экспорт журнала в CSV (UTF-8 BOM для Excel) и JSON. CSV экранирует спецсимволы
  и нейтрализует строки, похожие на формулы электронных таблиц.
- Кнопка очистки с подтверждением. До очистки рекомендуется экспортировать данные.

**Ограничения:** журнал не синхронизируется между компьютерами, не является
криптографически защищённым доказательством, и пользователь может менять его
записи. Избегайте секретов даже в названиях файлов/примечаниях. Это локальная
исследовательская версия, не для публичного интернета.

## Установка на Windows 11

1. Остановите Web 1.2 через `Ctrl+C` в PowerShell и закройте вкладку сайта.
2. Распакуйте содержимое `Code_Security_Analyzer_Web_1_3_Experiments.zip` в корень
   `code-security-analyzer`, **рядом с pom.xml**.
3. В PowerShell выполните:

```powershell
cd "E:\001 Satbayev University\diplom\Новая папка\code-security-analyzer"
$env:JAVA_HOME = "C:\Program Files\Eclipse Adoptium\jdk-21.0.12.101-hotspot"
$env:Path = "$env:JAVA_HOME\bin;$env:Path"

.\.venv-semgrep\Scripts\python.exe .\apply_web_v13.py
.\mvnw.cmd clean test
powershell -NoProfile -ExecutionPolicy Bypass -File ".\run-web.ps1"
```

4. Откройте `http://127.0.0.1:8080` и нажмите **Ctrl+F5**.
5. Загрузите `benchmark-dataset/java/Case008.java`, выберите `qwen2.5-coder:7b`,
   проведите аудит, нажмите на находку и создайте новое предложение исправления.
6. В блоке **05 / Эксперименты** появится новая запись с автоматическими
   результатами. После настоящих внешних тестов выберите запись, укажите статусы
   и имя файла лога, сохраните ручную оценку, экспортируйте CSV/JSON.

**Важно для ранее проверенного Case008:** предыдущий H2-лог относится к
конкретному предложению с контрольной суммой
`92e5d668fb769d6e5cb3f1f9706fe978a8143d48a20c9c083bba902ab9222517`.
Если новое предложение LLM имеет ДРУГОЙ SHA-256, нельзя переносить на него
статус 2/2 PASSED: проведите внешние функциональные тесты для нового файла.
При полном совпадении SHA-256 и проверенных условий можно вручную
документировать ранее проведённый внешний тест; файл лога должен быть сохранён.

## Проверки

Скрипт установки создаёт резервные копии в `web-v13-backup` и прекращает работу,
не перезаписывая локальные правки, если файлы не совпадают с Web 1.2. Повторная
установка уже установленной Web 1.3 ничего не меняет.

Разработческий JavaScript тест (Node.js опционален):

```powershell
node .\web-v13-files\tests\test_web_journal.cjs
```

Для приложения нужен JDK 21 и уже работавший Web 1.2. Функции ядра Java не
меняются, но `mvnw clean test` рекомендуется запускать обязательно. Сайт остаётся
доступен только с текущего компьютера через `127.0.0.1`.
