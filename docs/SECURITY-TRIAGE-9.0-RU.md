## Предварительное заключение

Для **классической shell-командной инъекции** явных данных недостаточно: передаётся массив аргументов вместо одной команды для `cmd.exe`/`sh`, а вызовы инструмента и источники пути ограничены. Однако мы **не присваиваем** находкам окончательный статус false positive без целевой проверки всех входов и Windows-особенностей. Для диплома зафиксировать `NEEDS_REVIEW` / «требует проверки».

## Проверки перед окончательным релизом

- [ ] Проверить, что пользовательский исходный код не способен задавать исполняемый файл Semgrep или `java.home`.
- [ ] Проверить, что override `analyzer.semgrep.executable` доступен только доверенной конфигурации.
- [ ] Проверить позитивные/негативные пути и относительные имена файлов, включая пробелы и имена с `-`.
- [ ] Проверить время ожидания и политику очистки временных файлов на Windows.
- [ ] Убедиться, что `javac` не запускает LLM-код и обработчики аннотаций, а зависимости проекта не могут незаметно попасть в classpath.
- [ ] Рассмотреть отдельную ОС-песочницу/контейнер для обработки враждебного кода в дальнейших версиях.
- [ ] Зафиксировать персонально подтверждённый статус каждой находки и приложить лог ручной проверки.

**Не делаем:** не отключаем правило, не помечаем ошибки как автоматически исправленные и не выдаём зелёный CI за отсутствие рисков. Продолжение работы 9.0 возможно как release candidate с явно открытыми вопросами.
