# Code Security Analyzer — Web 1.7: Advanced Security Dashboard

**Основа:** проверенная пользователем Web 1.6: `211 tests, BUILD SUCCESS`, 21.11.2026.
**Тип релиза:** небольшой патч фронтенда поверх Web 1.6, а не полный Java-проект.

## Что добавлено

- **02.В / Security Dashboard**: фильтры по тексту, риску, источнику (`LLM` / `Semgrep`), *заявленному* CWE и статусу ручной проверки. Фильтры меняют только отображение строк, не удаляют сигналы и не меняют JSON/HTML-экспорт.
- **Независимые счётчики**: LLM-сигналы, Semgrep-сигналы, непроверенные цитаты, возможные ложные срабатывания. Совпадения LLM + Semgrep по-прежнему отдельные и считаются лишь подсказкой для ручной сверки.
- **Возможный FP**: осторожный статус при `DEFENSE_PRESENT` (например, параметризованный SQL с `PreparedStatement`) или `LIKELY_FALSE_POSITIVE` из консультационного ИИ-ревью. Это **не автоматическое снятие находки** и не доказательство безопасности; оригинальные предупреждения остаются в таблице, истории и экспортах.
- **CWE conflict / непроверенная цитата**: отдельные категории для имеющихся в Web 1.6 метаданных. Некорректная цитата не выдаётся за ложный сигнал.
- **06.А / Сравнение моделей**: суммарное количество запусков, `COMPLETE`, `LIMITED`, ошибок и сигналов по названиям моделей из прежней истории Web 1.4–1.6. Пользовательские исходники, пути и описания находок в новые данные истории не добавляются.
- **HTML-отчёт Web 1.7**: содержит новую сводку и статус проверки рядом с каждым первичным сигналом. Исходники и предложенные исправления в HTML не включаются.

`Precision`, `Recall` и `F1-score` **не вычисляются по одному произвольному сканированию**: для них нужен фиксированный набор с эталонной разметкой. Счётчики истории, особенно по разным загружаемым файлам, не равнозначны сопоставлению точности моделей.

## Установка на Windows 11

1. Остановите веб-сервер `Ctrl+C`. Сделайте резервную копию всей папки `code-security-analyzer`. В браузере из разделов **05 / Эксперименты** и **06 / История аудитов** отдельно скачайте JSON, чтобы иметь копию локальных записей.
2. Распакуйте **содержимое** `Code_Security_Analyzer_Web_1_7_Advanced_Dashboard.zip` в корень проекта рядом с `pom.xml`. Не переносите вручную файлы из `web-v17-files` в `src` — это делает установщик.
3. В PowerShell выполните:

```powershell
cd "E:\001 Satbayev University\diplom\Новая папка\code-security-analyzer"

.\.venv-semgrep\Scripts\python.exe .\apply_web_v17.py
```

Если локальное виртуальное окружение недоступно, используйте `py -3 .\apply_web_v17.py`.

4. Проверьте, что **Maven использует Java 21**, а не Java 17 (после открытия нового окна PowerShell прежняя настройка `JAVA_HOME` могла сброситься):

```powershell
$javac = (Get-Command javac.exe).Source
$jdk21 = Split-Path (Split-Path $javac -Parent) -Parent
$env:JAVA_HOME = $jdk21
$env:Path = "$jdk21\bin;$env:Path"
.\mvnw.cmd -version
.\mvnw.cmd clean test
```

5. После `BUILD SUCCESS` запустите сервер:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\run-web.ps1"
```

Откройте <http://127.0.0.1:8080> и обновите страницу `Ctrl+F5`. В шапке должна отображаться **Web 1.7**.

## Проверка интерфейса

- **Case008.java + Mistral**: ожидается находка LLM и отдельный сигнал Semgrep; фильтр источника показывает их раздельно. Возможная пара отмечается только как предположение.
- **Case011.java + Mistral**: если LLM снова сообщит SQL Injection и Web 1.6 передаст статус `DEFENSE_PRESENT`, рядом появится **«Возможный FP»**. Находка останется в таблице и экспорте.
- **Case011.java + Qwen**: если модель выдаст 0 сигналов, пустая таблица должна ясно сообщать, что отсутствие находок не доказывает безопасность.
- **06.А**: сравнение моделей по сохранённым метаданным, без исходников.
- При использовании фильтров JSON/HTML должны сохранять **все** находки текущего отчёта, а не только показанные строки.

## Защита данных и безопасность установки

- Установщик проверяет SHA-256 целевых файлов версии 1.6 и всех файлов патча **до записи**. При конфликте пишет `ОСТАНОВЛЕНО` и ничего не перезаписывает.
- Изменяемые файлы сохраняются в `web-v17-backup/<дата>/...`. Повторный запуск идемпотентен.
- Патч меняет только файлы веб-интерфейса, не трогает JavaFX, Java/Ollama/Semgrep, датасет и локальное хранилище браузера.
- Сервер остаётся локальным прототипом. Не открывайте его в публичный Интернет без отдельной защиты доступа.
