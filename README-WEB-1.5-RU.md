# Code Security Analyzer — Web 1.5: LLM Evidence Diagnostics

Обновление предназначено для установленной **Web 1.4** (архив `Code_Security_Analyzer_Web_1_4_History_Insights.zip`).
Оно НЕ заменяет JavaFX, Semgrep, функциональные испытания, экспериментальный журнал и историю сканирований.

## Изменения

1. **02.Б / Проверка LLM:** отдельная панель показывает, какие LLM-находки не получили полной проверки и почему. Примеры категорий:
   - `EVIDENCE_FORMAT` — цитата отсутствует, слишком короткая или некорректно оформлена;
   - `EVIDENCE_MISMATCH` — цитата не совпадает с указанными исходными строками;
   - `EVIDENCE_NOT_VERIFIED` — качество цитаты не подтверждено, узкая причина не установлена;
   - `PARTIAL_CANDIDATES` — часть кандидатов ответа LLM потеряна или некорректна;
   - `LOCATION_NEEDS_REVIEW` — координаты нуждаются в ручной проверке.
2. JSON-отчёт дополнен полем `evidenceDiagnostic` у каждой находки: `modelOutputStatus`, `reasonCode`, `explanation`, `nextStep`. Эти поля **не содержат** исходный код, цитату модели, временные пути или полные исходные служебные сообщения.
3. В HTML-отчёт добавлена колонка «Причина LLM» (только код причины). Отчёт скачивается как `code-security-web15-report.html`.
4. **Ollama:** уточнены инструкции **уже существующей второй попытки**, если первая выдала некорректную цитату: модель должна дословно выбрать фрагмент из обозначенной L-строки. Это не автоматическое переписывание evidence и **не гарантирует** исчезновения `PARTIAL`.
5. Сохранились старые ключи хранения истории (`csa-web14-scan-history-v1`) — прежние записи Web 1.4 не потеряются, переименованы только имена экспортируемых файлов.
6. Добавлены 4 модульные проверки класса `WebFindingDiagnosticsTest`, JS-тесты и безопасный установщик с резервным копированием.

**Важно:** `CITATION_MATCHED` означает совпадение цитаты и местоположения, **не** доказательство реальной уязвимости. Статусы `PARTIAL` и `LIMITED` при невалидном ответе должны сохраняться — патч не маскирует неполноту.

## Установка в Windows 11

1. Остановите Web 1.4 нажатием `Ctrl+C` в PowerShell с работающим `run-web.ps1`.
2. **Скопируйте содержимое ZIP в корень проекта**, туда же, где `pom.xml`. Не удаляйте исходные файлы проекта. Сам ZIP не нужно распаковывать поверх `src` вручную: нужные файлы установит скрипт.
3. Запустите PowerShell:

```powershell
cd "E:\001 Satbayev University\diplom\Новая папка\code-security-analyzer"
.\.venv-semgrep\Scripts\python.exe .\apply_web_v15.py
.\mvnw.cmd clean test
powershell -NoProfile -ExecutionPolicy Bypass -File ".\run-web.ps1"
```

Если Python в `.venv-semgrep` отсутствует, используйте установленный Python 3: `py -3 .\apply_web_v15.py`.

4. Откройте `http://127.0.0.1:8080`, обновите `Ctrl+F5`, убедитесь, что вверху **Web 1.5**.
5. Загрузите `benchmark-dataset/java/Case008.java`, выберите `qwen2.5-coder:7b`, запустите аудит.
6. Если LLM вернёт `PARTIAL`, откройте **02.Б / ПРОВЕРКА LLM**, проверьте `reasonCode`, экспортируйте JSON и HTML-отчёт.
7. Проверьте `src/test/java/com/analyzerweb/WebFindingDiagnosticsTest.java` среди тестов Maven (проверяем результат `BUILD SUCCESS`, `Failures: 0`, `Errors: 0`).

## Защита локальных изменений

- Установщик проверяет **SHA-256** исходного `Web 1.4` интерфейса и `WebScanService.java` из Web 1.1, который не менялся в Web 1.2–1.4.
- Блок повторного вызова Ollama патчится **только при точном совпадении ожидаемого фрагмента**. Остальной `OllamaClient.java` не перезаписывается.
- При несоответствии **всё прекращается до записи**, с сообщением `ОСТАНОВЛЕНО`. Не нужно стирать свой код или принудительно ставить старые патчи — отправьте сообщение об ошибке для адресной адаптации.
- Перед изменением файлы копируются в `web-v15-backup/<дата>/`. Повторная установка ничего не дублирует. Если возникает ошибка установки, записанные в этом запуске файлы восстанавливаются.


### Ограничения

- Прототип работает только локально на `127.0.0.1`, его нельзя публиковать без отдельной модели доступа и безопасности.
- Исправления по-прежнему предлагаются отдельно и не применяются автоматически.
- Результаты модели и Semgrep — **сигналы, требующие ручной проверки**.
- Полная Maven-сборка и работа реальной Ollama на вашем Windows-компьютере должны быть проверены **после установки**; сборка архивного патча проводилась вне вашего локального окружения.
- Отчёт по-прежнему содержит имена файлов и описания находок, которые могут быть чувствительными. Не отправляйте его третьим лицам без проверки.
