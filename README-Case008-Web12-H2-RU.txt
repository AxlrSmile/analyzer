Case008 Web 1.2 — функциональная проверка CWE-89 на H2
============================================================

Что внутри:
- fix-validation/web12-case008/Case008.proposed.java — точная копия файла, присланного
  из Web 1.2, проверяемая по SHA-256
- fix-validation/web12-case008/Case008Web12JdbcTest.java — два JDBC-сценария
- fix-validation/web12-case008/run-case008-web12-h2.ps1 — сборка и запуск

SHA-256 предложения (UTF-8 после нормализации CRLF и Trim):
92e5d668fb769d6e5cb3f1f9706fe978a8143d48a20c9c083bba902ab9222517

Установка:
1) Распакуйте ZIP в корень code-security-analyzer рядом с pom.xml.
2) В PowerShell укажите JAVA_HOME на JDK 21.
3) Запустите из корня проекта:

powershell -NoProfile -ExecutionPolicy Bypass -File ".\fix-validation\web12-case008\run-case008-web12-h2.ps1" 2>&1 | Tee-Object -FilePath ".\fix-validation\Case008-Web12-H2.log"
if ($LASTEXITCODE -ne 0) { throw "H2 functional test failed" }

Тест использует только временную in-memory базу H2 c синтетическими пользователями.
Он не открывает реальные БД, не меняет проектные Java-файлы. Исходники компилируются
в отдельных временных каталогах. При отсутствии H2 2.3.232 скрипт попросит Maven
скачать тестовую зависимость; при наличии ранее загруженного jar интернет не нужен.

Ожидается:
- baseline: обычный запрос находит alice, специальный ввод показывает уязвимое
  поведение оригинала (две записи вместо одной);
- candidate: обычный запрос находит alice, специальный ввод не возвращает строк;
- RESULT: CANDIDATE FUNCTIONAL TESTS PASSED 2/2.

СООБЩЕНИЕ ОБ ОГРАНИЧЕНИЯХ
Отдельная проверка javac/API/Semgrep Web 1.2 уже показана на скриншотах пользователя,
но это другой тип проверки. До запуска данного скрипта функциональный результат
сохраняется как NOT_CHECKED. Два сценария H2 не доказывают абсолютную безопасность.
Запускайте только доверенный и просмотренный код из этого архива.
