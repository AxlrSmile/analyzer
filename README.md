# Code Security Analyzer — DevSecOps + локальные LLM-агенты

**Состояние:** исследовательский прототип; подготовка версии **9.0 (release candidate)**.\
**Репозиторий:** https://github.com/AxlrSmile/analyzer\
**Стек:** Java 21, Spring Boot 4.1, JavaFX, локальная Ollama (`qwen2.5-coder:7b`), Semgrep, Maven, Python 3.

Приложение помогает проводить аудит исходного Java-кода, сопоставлять выводы LLM и Semgrep, генерировать **предложения** по исправлениям и документировать результаты их проверки. Оно не подтверждает автоматически отсутствие уязвимостей и **не применяет изменения без участия человека**.

## Компоненты и границы доверия

| Компонент | Задача | Ограничение |
| --- | --- | --- |
| Security Scanner / Reviewer / Validator Agents | Локальный LLM-анализ и согласование выводов | Модель может ошибаться, галлюцинировать и пропускать CWE |
| SemgrepCliService | Запуск Semgrep с `p/default`, анализ JSON | 0 находок не доказывает безопасность; нужны доверенные инструменты и правила |
| Fix Recommendation Agent (8.7) | Черновик полного Java-файла, diff, отдельный экспорт | Не перезаписывает исходник и не запускает предложение |
| Fix Validation Agent (8.8) | Независимая компиляция исходника и предложения, предварительная оценка API | Не доказывает сохранение поведения; JDK — не ОС-песочница |
| Fix Experiments (8.9) | CWE-чек-листы, ручные статусы тестов, журнал, CSV/MD/SVG | `SKIPPED`/`NOT_CHECKED` нельзя считать успехом; журнал хранится в памяти до экспорта |
| Release preflight (9.0 RC) | Проверка состава файлов, SHA-256 датасета, настроек CI, Git и опционально JSON Semgrep | **Не выполняет** Java, Maven, Semgrep, LLM или пользовательский код |

Архитектура и методика: [docs/ARCHITECTURE-9.0-RU.md](docs/ARCHITECTURE-9.0-RU.md).

## Запуск на Windows 11

Требуются **JDK 21**, локальная [Ollama](https://ollama.com/) и модель `qwen2.5-coder:7b` для LLM-функций; отдельная среда с Semgrep для SAST. Не отправляйте секреты, закрытые исходники и приватные ключи в недоверенные модели или сторонние сервисы.

В PowerShell из корня проекта:

```powershell
java -version
.\mvnw.cmd clean test

# Python-тесты CLI/экспериментальных скриптов
.\.venv-semgrep\Scripts\python.exe -m unittest discover -s scripts/tests -p 'test_*.py' -v

# Статическая проверка полноты релизного кандидата (без запуска Java/LLM)
.\.venv-semgrep\Scripts\python.exe scripts/release_preflight.py --root .
```

Для UI запускать приложение из настроенной среды JavaFX/IntelliJ через `com.analyzer.CodeSecurityAnalyzerApplication.main`, предварительно запустив Ollama. Если Maven-профиль локально настроен для графического запуска, можно использовать его; в CI графический интерфейс не запускается. Сканирование требует доступного Semgrep (`.venv-semgrep` или PATH).

Проверьте набор тестов перед выпуском: для **8.9** подтверждены **185 Java + 15 Python**, в 9.0 RC добавлено **16 Python-проверок релизной готовности** (ожидается **31 Python**), Java-код не изменён. Общие 216 тестов — ожидаемая сумма **после** полного прогона 9.0 на машине разработчика, а не уже подтверждённый результат новой версии.

## Пример безопасного демонстрационного сценария

1. Откройте `benchmark-dataset/java/Case008.java` (учебный SQL injection) и выполните аудит.
2. Получите предложение LLM и просмотрите diff, исходник и предложенный код.
3. Проверьте компиляцию и API; запустите повторный Semgrep; отдельными тестами проверьте обычный запрос и ввод с SQL-метасимволами.
4. Зафиксируйте **реально выполненные** сценарии в журнале 8.9. Не переносите черновик автоматически в исходный проект.
5. Для `Case002.java` (Path Traversal) пометьте symlink-проверку `SKIPPED`, если ОС её не позволила провести; `0 → 0` Semgrep не означает исправление.
6. Экспортируйте CSV/MD; постройте SVG через `scripts/plot_fix_experiments.py`. Экспорт не перезаписывает существующие файлы.

Подробный сценарий и контрольный список: [docs/DEMO-RELEASE-CHECKLIST-RU.md](docs/DEMO-RELEASE-CHECKLIST-RU.md).

## CI и две находки Semgrep на этапе 8.9

На коммите [`95d8a14`](https://github.com/AxlrSmile/analyzer/commit/95d8a14b1652852de39ef5ba5f0798d150774595) workflow [DevSecOps CI](https://github.com/AxlrSmile/analyzer/actions/runs/43250428104) завершился **Success**: Java-тесты и сканирование Semgrep прошли, 44 Java-файла были просканированы. При этом Semgrep сообщил **2 срабатывания уровня ERROR**, оба по `ProcessBuilder` (строки `SemgrepCliService.java:67` и `FixValidationService.java:139`), без диагностики ошибок сканера. CI остаётся зелёным, потому что по умолчанию `SEMGREP_FAIL_ON=none`.

Эти срабатывания **не подтверждены как уязвимости** и **не закрыты**; требуется ручная оценка границ доверия и внешних исполняемых файлов. См. [docs/SECURITY-TRIAGE-9.0-RU.md](docs/SECURITY-TRIAGE-9.0-RU.md). Не подавляйте правила и не включайте блокирующий gate, пока срабатывания не расследованы.

## Подготовка 9.0 RC

```powershell
# Проверка без запуска LLM/Java (в рабочей папке даст WARN из-за отсутствия .git)
.\.venv-semgrep\Scripts\python.exe scripts/release_preflight.py --root .

# В Git-клоне можно сохранить отчёт, не перезаписывая существующий файл
.\.venv-semgrep\Scripts\python.exe scripts/release_preflight.py --root . --report release-preflight-9.0-local.json

# При наличии настоящего JSON Semgrep отдельно оцениваем findings и diagnostics
.\.venv-semgrep\Scripts\python.exe scripts/release_preflight.py --root . --semgrep-json ci-reports/semgrep.json
```

Скрипт возвращает код `1` при `FAIL`, `0` при `PASS/WARN`; предупреждение не равно подтверждению безопасности. Не коммитьте автоматически сформированные локальные отчёты.

## Ограничения

- Пилотный benchmark: **20 искусственных Java-файлов** (10 помеченных vulnerable, 10 safe *в отношении выбранной CWE*). Результаты не обобщаются на промышленный код.
- LLM иногда формирует частичные или некомпилируемые предложения. `PASSED` в компиляторе означает только успешную техническую проверку.
- Функциональные тесты потенциально небезопасного кода запускать только отдельно, в контролируемой среде и с учебными данными; это приложение **не выполняет** такие тесты.
- CLI-инструменты из PATH, JDK и системные параметры приложения следует считать доверенной конфигурацией разработчика. Нет полной изоляции на уровне ОС.
- Для публичного репозитория исключайте `.env`, локальные Python venv, отчёты со сниппетами и предложенный код из экспериментальных файлов.
