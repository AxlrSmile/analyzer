# Code Security Analyzer — Web 1.2: безопасный просмотр LLM-исправлений Java

Обновление поверх установленной Web 1.1. JavaFX, Semgrep/LLM-ядро, GitHub и desktop-интерфейс не изменяются.

## Что добавлено

- Выбор конкретной находки в таблице после анализа ZIP или отдельных исходных файлов.
- Для `.java`: кнопка «Сгенерировать и проверить исправление» с выбранной Ollama-моделью.
- **Новый API** `/api/fix-preview`, который принимает исходник и сведения о конкретной находке. Эти сведения рассматриваются как недоверенные и НЕ являются подтверждением уязвимости.
- Предложение создаёт существующий `FixRecommendationAgent`, без записи в проект.
- Предварительная проверка `FixValidationService`: компиляция через JDK и сравнение API. Исходный код НЕ запускается.
- Если Java-компиляция PASSED, `FixReviewService` отдельно прогоняет Semgrep до/после, если Semgrep доступен. Ноль находок не означает полной безопасности.
- В браузере отображаются оригинал и предложение рядом, построчный diff и диагностика. Предложенный код можно сохранить как **отдельный** файл, оригинал не перезаписывается.
- Python/Go/JavaScript/C++ по-прежнему доступны для **анализа** в Web 1.1, но автоматический Java-валидатор исправлений к ним не применяется. Поддержку других языков предложений добавим отдельно.

## Установка на Windows

1. Закройте JavaFX и окно запущенного `run-web.ps1` (Ctrl+C).
2. Распакуйте ZIP в корень `E:\001 Satbayev University\diplom\Новая папка\code-security-analyzer`, рядом с pom.xml.
3. Откройте PowerShell:

```powershell
cd "E:\001 Satbayev University\diplom\Новая папка\code-security-analyzer"
$env:JAVA_HOME = "C:\Program Files\Eclipse Adoptium\jdk-21.0.12.101-hotspot"
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
.\.venv-semgrep\Scripts\python.exe .\apply_web_v12.py
.\mvnw.cmd clean test
powershell -NoProfile -ExecutionPolicy Bypass -File .\run-web.ps1
```

4. Откройте `http://127.0.0.1:8080`, нажмите Ctrl+F5.
5. Загрузите `benchmark-dataset/java/Case008.java` или `web-demo.zip` с Case008 и Case011, выполните анализ. Нажмите на **строку Case008** в таблице находок. Внизу страницы появится блок «04 / ПРЕДЛОЖЕНИЕ ИСПРАВЛЕНИЯ». Выберите модель `qwen2.5-coder:7b` и нажмите «Сгенерировать и проверить исправление».
6. Посмотрите компиляцию, API, Semgrep до/после, diff. Если модель вернёт некорректное предложение, оно может получить FAILED — это ожидаемый результат проверки. **Никогда не считайте PASSED доказательством полной безопасности.**

## Безопасность и ограничения

- Только `127.0.0.1:8080`. **Не публикуйте сайт в интернет**, пока не реализованы аутентификация, контроль доступа, отдельная очередь задач, изоляция процессов и ограничения ресурсов.
- Предложение LLM — недоверенный текст. Функциональные тесты не выполняются автоматически.
- Java-компиляция использует ограниченные временные каталоги, но **не является полноценной ОС-песочницей**. Не используйте модуль для проверки чужого непроверенного исходника за пределами учебной локальной среды.
- Загрузки ограничены 256 КБ/500 строк для одной Java-программы; запрос создаёт временный исходник и удаляет его после ответа. Предложение не сохраняется сервером автоматически.
- Источник/предложение находятся в браузере; экспорт JSON от Web 1.1 по-прежнему не включает исходный код.
- Новый endpoint не позволяет выполнить, применить или перезаписать предложенный код в исходном проекте.
- Слабое место обработки обрамляющих маркеров `[BEGIN SOURCE]` в текущем `FixRecommendationAgent` остаётся открытым: неправильные ответы LLM должны быть отклонены компиляцией, но отдельная доработка парсера ещё требуется.

## Проверки и воспроизводимость

В подготовленной среде проверены синтаксис JavaScript, структура HTML, отдельная `javac`-компиляция новых классов со стабами зависимостей, проверки входной политики и установщик. **Полная сборка Maven со Spring Boot и фактическая работа LLM на Windows пока не проверены**. Отладочные заглушки в архив НЕ входят.
