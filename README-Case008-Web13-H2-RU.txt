СРАВНЕНИЕ С WEB 1.2
Содержательно код совпадает с предыдущим предложением Web 1.2.
Разница в одном пустом абзаце между import и public class.
Тем не менее SHA-256 другой, поэтому тест создаёт ОТДЕЛЬНОЕ
подтверждение именно Web 1.3. Старый журнал не изменяется.

СОДЕРЖИМОЕ
- fix-validation/web13-case008/Case008.proposed.java — точная копия загруженного файла
- fix-validation/web13-case008/Case008Web13JdbcTest.java — учебные H2/JDBC-сценарии
- fix-validation/web13-case008/run-case008-web13-h2.ps1 — проверка SHA и запуск

УСТАНОВКА И ЗАПУСК (Windows PowerShell)
1. Распакуй архив в корень code-security-analyzer (рядом с pom.xml).
2. В PowerShell перейди в корень и установи JDK 21 в JAVA_HOME.
3. Запусти:

powershell -NoProfile -ExecutionPolicy Bypass -File ".\fix-validation\web13-case008\run-case008-web13-h2.ps1" 2>&1 | Tee-Object -FilePath ".\fix-validation\Case008-Web13-H2.log"
if ($LASTEXITCODE -ne 0) { throw "Web 1.3 H2 test failed" }

Скрипт проверяет точную версию предложения, компилирует оригинал и
предложение в отдельных временных папках, создаёт только in-memory H2,
заполняет двумя СИНТЕТИЧЕСКИМИ записями и проверяет два сценария.

Ожидается:
- Оригинал: обычный запрос возвращает alice; специальный ввод даёт
  лишние строки — учебное воспроизведение SQL-инъекции.
- Предложение: обычный запрос возвращает alice; специальный ввод
  возвращает 0 строк (использована параметризация PreparedStatement).
- RESULT: CANDIDATE FUNCTIONAL TESTS PASSED 2/2.

При отсутствии H2 2.3.232 в fix-validation/lib/ скрипт обратится к
локальному Maven, чтобы получить зависимость. Может потребоваться интернет.

ВАЖНО
Этот Java-код предварительно просмотрен, но запуск Java/скрипта
выполняй только на собственном компьютере с доверенными файлами.
Результат относится лишь к двум учебным H2-сценариям и не доказывает
абсолютную безопасность исправления.
