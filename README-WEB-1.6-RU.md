# Code Security Analyzer — Web 1.6 (LLM Accuracy & Reliability)

**Базовая версия:** рабочая Web 1.5 после `203 tests, BUILD SUCCESS` (21 ноября 2026).
**Тип релиза:** точечный локальный патч (не полный исходный проект).

## Изменения

1. `EvidenceRetryHints` формирует дополнительную, **ограниченную по объёму** подсказку для второго вызова Ollama, **только если** предыдущая проверка цитаты `evidence` не прошла. В подсказку включаются существующие оригинальные строки около указанных моделью координат, например вокруг L5/L6. Если ответ модели не содержит разборных координат, подсказка пропускается. Ни в JSON-отчёт, ни в историю аудитов текст кода из этой подсказки не записывается.
2. Проверка `StructuredEvidencePreflight` остаётся обязательной. Мы не подставляем автоматически цитаты, не переносим находки на другую строку без ответа модели и не меняем непроверенный `PARTIAL` на `COMPLETE`.
3. В метаданных ответа API для LLM-находок появились `cweAdvisorStatus`, `cweSuggestion` и `mechanismStatus`. Эти статусы уже вычислялись существующими Java-сервисами. Web 1.6 показывает только разрешённые коды статусов и корректные коды CWE; исходный код, цитаты и внутренние свободные примечания не включаются.
4. В разделе **02.Б / Проверка LLM** появились предупреждения о возможном несоответствии категории CWE и исходного кода. CWE, предложенный моделью, не переписывается, а предупреждение не является доказательством эксплуатации или ложной тревоги.
5. Интерфейс и HTML-отчёт обозначены как **Web 1.6**. Существующие функции Web 1.5 (история, экспорт, WebFix, JavaFX) оставлены без изменения бизнес-логики.
6. Включены новые тесты: 4 для генерации подсказок, 3 для безопасной CWE-проекции и 1 для повторного запроса Ollama с локальным тестовым HTTP-сервером.

## Установка Windows 11

1. Остановите сервер `run-web.ps1` через `Ctrl+C`.
2. Сделайте копию всей папки проекта. Сохраните отдельно JSON-экспорт истории браузера и журнала экспериментов (их хранит браузер, не Java-проект).
3. Распакуйте **содержимое ZIP** в `E:\001 Satbayev University\diplom\Новая папка\code-security-analyzer`, рядом с `pom.xml`. Вручную не копируйте файлы из `web-v16-files` в `src` — это делает установщик.
4. В PowerShell из корня проекта:

```powershell
.\.venv-semgrep\Scripts\python.exe .\apply_web_v16.py
.\mvnw.cmd -version
.\mvnw.cmd clean test
powershell -NoProfile -ExecutionPolicy Bypass -File ".\run-web.ps1"
```

Если Python из виртуального окружения не найден, используйте `py -3 .\apply_web_v16.py`. **Maven должен показывать Java 21**, иначе проверьте `JAVA_HOME` (раньше Maven запускался через Java 17, несмотря на установленный `javac 21`).

5. Откройте `http://127.0.0.1:8080`, нажмите `Ctrl+F5` и проверьте надпись **Web 1.6**.
6. Протестируйте `benchmark-dataset/java/Case008.java` с `qwen2.5-coder:7b`, затем отдельно `Case011.java`. Ожидается SAST-сигнал на Case008 и отсутствие SQL-сигнала на контрольном Case011; LLM может остаться в PARTIAL — это допустимый честный результат.
7. Для количественной оценки 20 файлов выполните эксперименты отдельно и сравните экспорт с `benchmark-dataset/ground_truth.json`. Никаких новых результатов без реального запуска не заявляйте.

## Безопасность установки

- Установщик работает офлайн, сверяет SHA-256 файлов Web 1.5, проверяет полезную нагрузку и перед записью создаёт резервные копии в `web-v16-backup/<дата>`.
- Изменяет `OllamaClient.java` **только в проверенном блоке Web 1.5**. Неизвестная локальная версия или конфликт файлов вызывает `ОСТАНОВЛЕНО`, без попытки перезаписать локальные правки.
- Повторное применение патча не меняет файлы. Тестируемые учебные исходники не выполняются.
- Система и встроенный Ollama предназначены для локального использования, не для публикации в Интернет без отдельной защиты доступа.

## Локальные тесты, которые можно выполнить отдельно

```powershell
node .\web16-tests\test_web16_diagnostics.cjs
py -3 .\web16-tests\test_installer.py
```

**Границы проверки релиза до установки:** тесты Node.js и установщика пройдены, а Java-классы с отдельными заглушками скомпилированы и выполнены изолированные проверки. Полную Maven-сборку в твоей текущей Windows-среде и реальные вызовы Ollama должен подтвердить отдельный локальный запуск после установки. Это не означает, что уязвимости всегда будут найдены или что исправления всегда безопасны.
