# Code Security Analyzer — Web 1.0 (локальная браузерная версия)

## Что уже работает

Веб-страница `http://127.0.0.1:8080/` запускается с теми же Java-сервисами, что и JavaFX:
`UnifiedScanService`, Ollama, Semgrep, проверка местоположения/доказательств и AI reviewer.

- Светлая и тёмная темы.
- Список моделей из локальной Ollama (когда Ollama недоступна, сервис может вернуть имя модели по умолчанию).
- Одновременная загрузка 1–5 файлов на поддерживаемых языках (Java, Python, JS/TS, Go, C/C++, C#, Kotlin, Scala, Rust, PHP, Ruby, SQL).
- Поиск находок с уровнями HIGH/MEDIUM/LOW, CWE, строками, описанием и рекомендациями.
- Отдельные признаки полноты Semgrep и LLM; неполная проверка не выдаётся за чистый результат.
- Экспорт результатов в JSON в браузере.
- JavaFX-приложение продолжает запускаться без параметра `--web`.

**Эта версия предназначена только для localhost (127.0.0.1), а не для публичного хостинга.**

## Установка поверх текущего проекта (UI v1–v8)

1. Закройте JavaFX-приложение.
2. Распакуйте **всё содержимое** архива в папку `code-security-analyzer`, рядом с `pom.xml`.
3. В PowerShell из корневой папки:

```powershell
$env:JAVA_HOME = 'C:\Program Files\Eclipse Adoptium\jdk-21.0.12.101-hotspot'
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
.\.venv-semgrep\Scripts\python.exe .\apply_web_v1.py
.\mvnw.cmd clean test
```

Если `python.exe` из Semgrep-окружения недоступен, можно выполнить `py -3 .\apply_web_v1.py`.

4. Запустите веб-сервер:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\run-web.ps1
```

5. Откройте в браузере **http://127.0.0.1:8080/**.
6. Выберите модель, затем несколько **учебных** исходников, например из `benchmark-dataset/java`, и нажмите «Запустить анализ».
7. Дождитесь результата; скачайте JSON. Когда нужно остановить сайт, нажмите **Ctrl+C** в окне PowerShell.

Если порт 8080 занят, завершите другой процесс на этом порту. Для локальной демонстрации можно выбрать другой порт командной строкой Spring Boot, но сохраняйте адрес `127.0.0.1`.

## Как устроена интеграция

- `CodeSecurityAnalyzerApplication.main()` при `--web` вызывает `WebServerApplication.start(...)`; без `--web` остаётся JavaFX.
- `JavaFxApplication` запускает Spring с `WebApplicationType.NONE`, чтобы после добавления WebMVC desktop не поднимал HTTP-сервер.
- В отдельном пакете `com.analyzerweb` находится Spring Boot конфигурация, которая не сканируется JavaFX-конфигурацией.
- `/api/models` возвращает список моделей (GET).
- `/api/scan` принимает multipart-файлы и выбор модели (POST). Требуется заголовок `X-Code-Analyzer: web1`, чтобы предотвратить простую CSRF-отправку форм со сторонних сайтов.
- Файлы проверяются до записи, затем записываются в новый временный каталог, анализируются существующим `UnifiedScanService` и удаляются после запроса. Веб-API не раскрывает локальные абсолютные пути и содержимое файлов в ответе.
- Semgrep запускается в режиме scan без shell и без autofix; если найден `.venv-semgrep` в рабочем каталоге приложения, его путь передаётся через `analyzer.semgrep.executable`.

## Ограничения и честное описание результатов

- Не более **5 файлов**, максимум **256 КБ на файл**, **512 КБ суммарно** и **500 строк на файл**.
- Только загрузка отдельных файлов: ZIP-проекты и деревья папок пока не поддерживаются. Файлы с одинаковым именем не принимаются.
- Веб-запрос пока синхронный. Долгий ответ Ollama может занять минуты. Одновременно допускается один анализ.
- Веб-версия **пока не умеет** предлагать патчи, выполнять Java-валидацию исправлений и экспортировать PDF. Эти функции остаются в JavaFX и могут быть добавлены отдельным этапом.
- Исходный код не исполняется. Однако анализаторы обрабатывают недоверенный текст: не загружайте реальные секреты, не открывайте прототип в публичную сеть.
- В приложении нет учётных записей, полноценной изоляции контейнеров, очереди заданий и контроля доступа для интернета. Публикация на сервере требует отдельной модели безопасности.
- Веб-демонстрация использует локальную Ollama. Если она не запущена, LLM-проверка может завершиться с ошибкой; интерфейс покажет диагностику.
- Ноль находок или совпадение LLM/SAST не является доказательством отсутствия уязвимостей.

## Для дальнейшего развития

Web 1.1: поддержка ZIP-проектов с безопасной распаковкой, фоновые задания и прогресс, сохранение истории результатов. Web 1.2: diff и контролируемая проверка предложений исправлений. До публичного размещения нужны авторизация, изоляция сканирования, квоты и правила обработки загружаемого исходного кода.
